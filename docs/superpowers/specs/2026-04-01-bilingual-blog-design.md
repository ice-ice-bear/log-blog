# Bilingual Blog Support — Design Spec

## Context

The blog `ice-ice-bear.github.io` uses Hugo Stack theme with a directory-based multi-language structure (`content/ko/posts/`, `content/en/posts/`). Currently all 154 posts are Korean-only. The goal is to:

1. Switch `defaultContentLanguage` to `en` and enable Hugo's `languages` config
2. Modify the logblog post skill to auto-translate posts (Korean original → English rewrite) and publish to both language directories
3. Translate existing 118 2026-era Korean posts to English (separate session)

## 1. Hugo Blog Multilingual Config

### `hugo.yaml` changes

```yaml
# CHANGE: ko → en
defaultContentLanguage: en

# ADD: languages section
languages:
  en:
    languageName: English
    weight: 1
  ko:
    languageName: 한국어
    weight: 2
    hasCJKLanguage: true
```

### Content directory structure

```
content/
├── en/
│   ├── posts/          ← English posts (default language)
│   ├── archives.md
│   └── search.md
├── ko/
│   ├── posts/          ← Korean posts (existing 154)
│   ├── archives.md
│   └── search.md
└── posts/              ← legacy, no longer used for new posts
```

### Language switcher

Stack theme has a built-in language switcher in `_partials/sidebar/left.html` that renders a `<select>` dropdown when `languages` config exists. No custom template needed.

Posts with the same filename in both `content/en/posts/` and `content/ko/posts/` are automatically linked as translations.

## 2. Logblog Skill Changes

### Post skill (`skills/post/SKILL.md`)

Add **Step 5.5: Translation** between post writing and user review:

```
Step 5:   Write original post (Korean by default)
Step 5.5: Generate English translation (Claude rewrites for English audience)
Step 6:   User reviews both versions
Step 7:   Sequential publish:
          publish post-ko.md --filename "slug.md" --language ko --cover-title "..." --tags "..."
          publish post-en.md --filename "slug.md" --language en --cover-title "..." --tags "..." --no-images
```

### Translation guidelines (embedded in skill)

- Rewrite for English audience, not literal translation
- Technical terms follow English conventions (e.g., 분산 추적 → distributed tracing)
- Translate: `title`, `description` in frontmatter, body text, Mermaid diagram labels
- Keep unchanged: `tags`, `categories`, `date`, `image`, code blocks, URLs
- Same `--filename` ensures Hugo translation linking
- English publish uses `--no-images` (cover already generated by Korean publish)

### Setup skill (`skills/setup/SKILL.md`)

Phase 3B Step 2.5: Detect `languages` section in Hugo config and populate `language_content_dirs` accordingly.

Phase 3A Step 1: Ask about multi-language support, offer en/ko as preset.

### Config (`config.yaml`)

Already implemented:

```yaml
blog:
  content_dir: "content/posts"
  language_content_dirs:
    ko: "content/ko/posts"
    en: "content/en/posts"
  default_language: "en"
```

## 3. Existing Post Translation

### Scope

- 118 posts matching `content/ko/posts/2026-*.md`
- 2024/2025 posts excluded (36 posts)

### Process

- Separate session (token-intensive)
- Parallel Claude agents: each handles 10-15 posts
- Read Korean → rewrite English → save to `content/en/posts/` with same filename
- Translate frontmatter `title`, `description`, body, Mermaid labels
- Keep `tags`, `categories`, `date`, `image` unchanged
- Bulk git commit + push after completion
